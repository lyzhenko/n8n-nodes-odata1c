# Публикация стандартного интерфейса OData в 1С:Предприятии

Нода работает с сервисом OData, который платформа 1С создаёт автоматически. В конфигурации ничего программировать не нужно, но на стороне 1С должны выполняться три условия:

1. База опубликована на веб-сервере с включённым стандартным интерфейсом OData.
2. Нужные объекты метаданных включены в состав OData.
3. Есть отдельный пользователь с необходимыми правами.

## 1. Опубликовать базу

### Windows / IIS или Apache (Конфигуратор)

1. Откройте базу в Конфигураторе.
2. **Администрирование → Публикация на веб-сервере**.
3. Задайте имя публикации (например `erp`), веб-сервер и каталог.
4. Включите флажок **Публиковать стандартный интерфейс OData**.
5. Опубликуйте и проверьте адрес:

```bash
curl -i -u odata_user:password https://1c.example.com/erp/odata/standard.odata/$metadata
```

HTTP 200 и EDMX-документ означают, что сервис работает. HTTP 401 — проблема аутентификации; HTTP 404 — публикация или интерфейс OData отключены.

### Linux (webinst, default.vrd)

Публикация создаётся командой `webinst -publish -apache24 -wsdir erp -dir /var/www/erp -connstr "Srvr=localhost;Ref=erp"`. Интерфейс OData включается в `default.vrd`:

```xml
<point xmlns="http://v8.1c.ru/8.2/virtual-resource-system"
       xmlns:xs="http://www.w3.org/2001/XMLSchema"
       base="/erp"
       ib="Srvr=localhost;Ref=erp">
  <standardOdata enable="true"
                 reuseSessions="autouse"
                 sessionsTimeout="20"
                 poolSize="10"
                 maxBufferSize="10000000"
                 readWriteMode="readwrite"/>
</point>
```

`readWriteMode` — `readwrite`, `readonly` или `writeonly`. `reuseSessions="autouse"` позволяет 1С переиспользовать сеансы для запросов OData.

## 2. Задать состав OData

По умолчанию состав пустой, и любой запрос отвечает «Сущность … не найдена». Состав задаётся методом платформы `УстановитьСоставСтандартногоИнтерфейсаOData`:

```bsl
Процедура НастроитьСоставOData() Экспорт
	Состав = Новый Массив;
	Состав.Добавить(Метаданные.Справочники.Номенклатура);
	Состав.Добавить(Метаданные.Справочники.Контрагенты);
	Состав.Добавить(Метаданные.Справочники.Валюты);
	Состав.Добавить(Метаданные.Документы.ЗаказКлиента);
	Состав.Добавить(Метаданные.РегистрыСведений.ЦеныНоменклатуры);

	УстановитьСоставСтандартногоИнтерфейсаOData(Состав);
КонецПроцедуры
```

Объекты, на которые ссылаются включённые объекты, тоже должны быть в составе — иначе 1С не даст сохранить состав. В конфигурациях на БСП для этого есть форма **Настройка стандартного интерфейса OData** и обработка **Настройка автоматического REST-сервиса**, которые подбирают зависимые объекты и создают служебного пользователя.

## 3. Создать пользователя интеграции

* Отдельный пользователь, например `odata_user`, с длинным случайным паролем.
* Только необходимые права: чтение — на объекты, которые читаем, запись/добавление — на объекты, которые меняем, плюс права на связанные объекты и табличные части.
* В конфигурациях на БСП есть отдельная роль для удалённого доступа к OData — назначайте её вместо полных прав.
* Никогда не используйте администратора для интеграции.

## 4. Проверить адреса

```bash
BASE=https://1c.example.com/erp/odata/standard.odata
AUTH='-u odata_user:password'

# корневой документ сервиса
curl $AUTH "$BASE/?\$format=json"

# метаданные (у ERP это могут быть десятки мегабайт)
curl $AUTH "$BASE/\$metadata" -o metadata.xml

# первые пять элементов справочника
curl $AUTH "$BASE/Catalog_Номенклатура?\$format=json&\$top=5&\$select=Ref_Key,Code,Description"

# количество с отбором
curl $AUTH "$BASE/Catalog_Номенклатура/\$count?\$filter=DeletionMark%20eq%20false"

# документ вместе с табличной частью
curl $AUTH "$BASE/Document_ЗаказКлиента(guid'6c4fce01-9d2a-11ee-8f3a-00155d0a1b2c')?\$format=json"
```

## Примечания

* **`$format=json` обязателен** для JSON-ответов; без него 1С вернёт Atom XML.
* **Аутентификация — HTTP Basic.** Публикуйте по HTTPS; не передавайте логин и пароль в URL.
* **Каждый запрос — сеанс 1С.** `reuseSessions` и `poolSize` в `default.vrd` снижают накладные расходы, но платформа всё равно открывает сеанс на запрос.
* **1С не декодирует `+` как пробел** в строке запроса. Нода отправляет пробелы как `%20`, поэтому фильтры пишутся с пробелами, а кодирование делает нода. При ручных вызовах используйте `%20`, а не `+`.
* **Не выставляйте OData в интернет** без обратного прокси, TLS и строгого пользователя. OData даёт полный CRUD в пределах прав пользователя.
